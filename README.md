# สุ่มคู่ลงสนาม — ตัวช่วยจัดคิวแบดมินตัน

เว็บหน้าเดียวสำหรับสุ่มจับคู่ตีแบดตามรายชื่อที่กรอก ไม่มี build step ไม่มี dependency
เปิดไฟล์ `index.html` ในเบราว์เซอร์ได้เลย

ใช้งานจริงที่ **https://soombadminton.pages.dev**

## ความสามารถ

- กรอกรายชื่อผู้เล่น (บรรทัดละคน หรือคั่นด้วย `,`) ตัดชื่อซ้ำอัตโนมัติ
- เลือกรูปแบบ **เดี่ยว 1:1** (2 คน/สนาม) หรือ **คู่ 2:2** (4 คน/สนาม)
- เลือกจำนวนสนาม **1–4 สนาม**
- เล่นคู่แต่คนไม่พอครบทุกสนาม (เช่น 7 คน 2 สนาม) ตอนกดสุ่มจะถามก่อนว่า
  จะให้สนามที่ว่างเล่น **เดี่ยว 1:1** มั้ย — ตอบ “ไม่ต้อง” ก็สุ่มแบบเดิมให้คนที่เหลือพัก, กด Esc ไม่สุ่มเลย
  สนาม 1:1 มีป้ายกำกับให้เห็นชัด และ “สุ่มรอบนี้ใหม่” ยังคงเป็น 1:1 ในสนามเดิม
  (เฉพาะโหมดสุ่มล้วน — ตารางวนครบทุกคู่ต้องคงการันตีว่าทุกคนได้จับคู่กันครบ)
- ชื่อไม่ซ้ำกันภายในรอบเดียวกันเสมอ
- วิธีจัดตาราง 2 แบบ
  - **สุ่มล้วน** — สุ่มใหม่ทุกครั้ง คนที่ยังไม่ได้ลงจะถูกจัดให้ลงก่อนในรอบถัดไป
  - **วนครบทุกคู่** — สร้างตารางหมุนเวียนทั้งชุด ทุกคนได้จับคู่กับทุกคน (โหมดเดี่ยวคือได้เจอกันครบทุกคน)
- **สลับตัวเองได้หลังสุ่มเสร็จ** — แตะชื่อหนึ่ง แล้วแตะอีกชื่อ สองคนนั้นจะลอยไปสลับที่กัน
  สลับข้ามสนาม ข้ามรอบ หรือสลับกับคนที่รอคิว/พักอยู่ก็ได้ (เช่น A ขอพัก เอา F ลงแทน)
  ถ้าสลับแล้วชื่อจะซ้ำกันในรอบเดียว ระบบจะไม่ยอมและบอกเหตุผล ส่วนสถิติลง/พักปรับตามให้อัตโนมัติ
- **จบเกมทีละสนาม** — การ์ดสนามในรอบ 1 (รอบที่กำลังเล่น) มีปุ่ม “จบเกม” สนามไหนตีเสร็จก่อนกดได้เลย
  คนชุดถัดไปจะลงสนามเบอร์เดิมทันที ไม่ต้องรอสนามที่ยังเล่นอยู่
  - ถ้ายังมีรอบที่จัดไว้ จะดึงแมตช์แรกที่ทุกคนว่างอยู่ขึ้นมา
    (ตารางวนครบทุกคู่ข้ามแมตช์ที่มีคนยังเล่นสนามอื่นไปก่อน สนามนั้นจะขึ้นว่า “ว่าง” จนกว่าจะมีคนว่างพอ)
  - แบบสุ่มล้วนเมื่อรอบที่จัดไว้หมดแล้ว จะสุ่มแมตช์ใหม่จากคนที่ว่าง โดยให้คนที่ลงน้อยสุดและรอนานสุดได้ก่อน
    แล้วแบ่งคู่ให้ซ้ำกับที่เคยจับน้อยที่สุด สนาม 1:1 ที่เปิดไว้ในโหมดคู่ยังเป็น 1:1 ต่อไป
  - เกมที่จบแล้วยังนับอยู่ในสถิติและความครบของตารางวนครบทุกคู่
- **จอใหญ่** — ปุ่มรูปจอมุมขวาบนเปิดหน้าที่มีแค่สนามที่กำลังเล่น ตัวใหญ่อ่านได้จากข้างสนาม
  พร้อมนาฬิกาและแถว “ต่อไป/คิวถัดไป” ด้านล่าง จัดกี่คอลัมน์ให้เองตามขนาดจอ (ทีวี แท็บเล็ต มือถือ)
  กดจบเกมและแตะชื่อเพื่อสลับตัว (ทั้งในสนามและแถวคิวถัดไป) จากจอนี้ได้เลย เปิดเต็มจอให้ถ้าเครื่องรองรับ และขอให้จอไม่ดับระหว่างเปิดอยู่ (Wake Lock)
  กด Esc หรือปุ่มกากบาทเพื่อออก
- **เสียงตีลูก** ตอนกดสุ่ม (ตี-รับสองจังหวะ) และตอนมีคนลงสนามใหม่ สร้างเสียงสด ๆ ด้วย Web Audio ไม่มีไฟล์เสียง
  ปิด/เปิดได้ที่ปุ่มลำโพงมุมขวาบน จำค่าไว้ที่คีย์ `badminton-sound` บน iPhone ถ้าเปิดโหมดเงียบไว้จะไม่มีเสียง
- **ป้ายสีประจำตัว** — ทุกชื่อมีวงกลมสีกับตัวอักษรแรก เห็นเหมือนกันทั้งในสนาม แถวรอคิว/พัก สถิติ และจอใหญ่
  สีเลือกจากตัวสะกดของชื่อ จึงได้สีเดิมทุกครั้ง และไม่ซ้ำกันจนกว่าจะเกิน 10 คน
  ชื่อที่ขึ้นต้นด้วยสระหน้า (เ แ โ ใ ไ) ใช้พยัญชนะตัวถัดไป เช่น เบล → บ
- กด **จบเกม** แล้วคนที่เล่นเสร็จเดินออกไปแถวรอคิว/พัก คนถัดไปเดินลงสนาม ใครย้ายที่ก็เห็นลอยไปทุกคน
- **การ์ดสรุปคืนนี้** (ปุ่มใต้สถิติใน “ค่าก๊วนและสถิติ”) — วาดเป็นรูป 1080×1350
  มีจำนวนเกม คนที่ลงสนาม ค่าก๊วนต่อคน 5 อันดับคนที่ลงมากสุด และคู่ที่จับคู่กันบ่อยสุดของคืนนั้น
  แชร์เข้า LINE ได้ตรง ๆ บนเครื่องที่รองรับการแชร์ไฟล์ หรือกดบันทึกรูป
- นับสถิติจำนวนครั้งที่ลง/พักของแต่ละคน และหมุนเวียนให้ยุติธรรม
  แต่ละแถวมีจุดเท่าจำนวนแมตช์ของคนที่ลงเยอะสุด จุดทึบคือแมตช์ที่ได้ลง จุดกลวงคือที่พลาดไป
  นับได้ด้วยตาว่าใครตามหลังอยู่กี่แมตช์ · ถ้าเป็นตารางวนครบทุกคู่ที่ยาวเกิน 12 แมตช์ จะกลับไปใช้แถบแทน
- ผังสนามวาดเส้นครบชุดตามมาตรฐาน BWF — กรอบคู่/เดี่ยว เส้นเสิร์ฟสั้น เส้นเสิร์ฟยาวคู่ และเส้นกลาง
  วาดจาก `<template>` เดียวที่ทุกการ์ดโคลนไป หน่วยใน viewBox คือเซนติเมตรจริง
  สลับเดี่ยว/คู่แล้วเส้นข้างที่ใช้จริงจะสว่างขึ้น อีกคู่หรี่ลง
  คนยืนในช่องเสิร์ฟ — คู่ยืนหน้า-หลังเฉียงกัน อีกฝั่งกลับด้านครึ่งรอบ ส่วนเดี่ยวยืนกลางฝั่ง
- หน้าตาเป็นแบบ **liquid glass** — แผงและการ์ดเป็นแผ่นโปร่งที่เบลอสิ่งที่อยู่ข้างหลัง
  มีเส้นแสงบนขอบบนและเงายกตัวออกจากพื้น ส่วนแถบปุ่มล่างบนมือถือเป็นแคปซูลลอยให้บอร์ดไหลผ่านใต้มัน
  เบราว์เซอร์ที่ไม่รองรับ `backdrop-filter` จะได้แผ่นทึบแทน (ผ่าน `@supports`) อ่านได้เหมือนกัน
- **ฉากเปิดแอป** — เริ่มจากภาพเดียวกับ splash ของ iPhone แล้วลูกขนไก่โดนตีหมุนหนึ่งรอบ ชื่อแอปลอยขึ้นมา
  จากนั้นพื้นเขียวหดขึ้นไปเป็นแถบหัว ลูกขนไก่บินเข้าไปเป็นโลโก้ และแผงต่าง ๆ ค่อย ๆ ลอยเข้าที่
  เล่นเต็ม ๆ ครั้งเดียวต่อการเปิด (รีโหลดในแท็บเดิมได้แค่แผงลอยเข้าสั้น ๆ) แตะจอเพื่อข้ามได้
  และถ้าเครื่องตั้ง “ลดการเคลื่อนไหว” ไว้จะข้ามไปเลย
- **โหมดสว่าง/มืด** ปรับตามการตั้งค่าของเครื่องเอง (`prefers-color-scheme`)
  และกดสลับเองได้ที่ปุ่มมุมขวาบน ถ้าสลับมาตรงกับที่เครื่องตั้งไว้ จะกลับไปตามเครื่องให้อัตโนมัติ
- บนมือถือ แผงตั้งค่าทั้งแผงถูกย่อเหลือบรรทัดเดียว (`12 คน · คู่ 2:2 · 2 สนาม`) แตะ “แก้ไข” จึงกางออก
  ส่วนปุ่มสุ่มลอยอยู่ล่างจอตลอด ไม่ต้องเลื่อนกลับขึ้นไปหา
- ปุ่มรีเซ็ตมี 2 ระดับ — **กดสั้น** ล้างผลจับคู่กับสถิติแต่เก็บรายชื่อไว้
  **กดค้าง 1 วินาที** (หรือ Shift+คลิก) จะถามยืนยันก่อนล้างทุกอย่างรวมรายชื่อ
- จำรายชื่อ การตั้งค่า สถิติ และผลจับคู่ล่าสุดไว้ใน localStorage ของเครื่องที่เปิด
  ปิดแท็บหรือมือถือดับจอแล้วเปิดใหม่ ก็ได้ของเดิมคืนทั้งชุด ไม่ต้องเริ่มนับหนึ่ง
  ถ้าเว้นไปเกิน 12 ชั่วโมงถือว่าคนละก๊วน สถิติจะเริ่มใหม่ แต่ยังจำรายชื่อกับการตั้งค่าไว้ให้
  (คีย์ `badminton-draw-v1` ส่วนโหมดสว่าง/มืดที่เลือกเองอยู่ที่ `badminton-theme` แยกกัน)

## หมายเหตุเรื่องการจับคู่ให้ครบ

หนึ่งแมตช์คู่ 2:2 ใช้ไป 2 คู่ ดังนั้นถ้าจำนวนคู่ทั้งหมด `n(n-1)/2` เป็นเลขคี่
(เช่น 6, 7, 10, 11 คน) จะเหลือ 1 คู่ที่ลงไม่ได้เสมอ — เป็นข้อจำกัดเชิงคณิตศาสตร์
ไม่ใช่บั๊ก ระบบให้ผลดีที่สุดเท่าที่เป็นไปได้ (เช่น 6 คน = 14 จาก 15 คู่)

## โครงสร้าง

```
index.html                ตัวเว็บทั้งหมดอยู่ในไฟล์เดียว (HTML + CSS + JS)
icon.svg                  โลโก้ลูกขนไก่ที่วาดด้วย SVG — ใช้เป็นไอคอนบนแท็บเบราว์เซอร์
logo-source.jpg           โลโก้ก๊วน “แบดมินตัน ฮับ” — ต้นฉบับของไอคอนหน้าจอโฮม
icon-180.png              apple-touch-icon สำหรับ “เพิ่มลงในหน้าจอโฮม” บน iOS
icon-192.png              ไอคอน Android และ favicon สำรองของเบราว์เซอร์เก่า
icon-512.png              ไอคอนความละเอียดสูง
icon-maskable-512.png     ไอคอนแบบ maskable ของ Android (เผื่อขอบให้โดนครอบตัด)
manifest.webmanifest      ชื่อ สี และรายการไอคอนสำหรับหน้าจอโฮม
sw.js                     service worker — ทำให้ติดตั้งเป็นแอปได้ และเปิดใช้งานตอนไม่มีเน็ต
_headers                  header ความปลอดภัยที่ Cloudflare Pages ส่งไปกับทุกไฟล์
splash/                   ภาพตอนเปิดแอปบน iPhone (apple-touch-startup-image) หนึ่งไฟล์ต่อขนาดจอ
```

ไฟล์ `icon-*.png` ครอปวงกลมโลโก้จาก `logo-source.jpg` ถ้าเปลี่ยนโลโก้ ให้ครอปใหม่ทุกขนาด
ตัว maskable เว้นขอบมากกว่าเพื่อน เพราะ Android จะครอบเป็นวงกลมหรือสี่เหลี่ยมมนแล้วแต่เครื่อง

> `viewport-fit=cover` ในแท็ก viewport เป็นตัวที่ทำให้ `env(safe-area-inset-*)` มีค่าบน iOS
> ถ้าไม่มี ค่าจะเป็น 0 เสมอ และแอปที่ติดตั้งแล้วจะวางแถบปุ่มล่างทับแถบ home indicator

> `apple-mobile-web-app-status-bar-style: black-translucent` ทำให้ iOS ทาตัวเลขนาฬิกาเป็นสีขาวเสมอ
> แถบเขียวด้านบน (`.masthead` + `.statusbar`) จึงยืดขึ้นไปคลุม `env(safe-area-inset-top)` ให้นาฬิกามีพื้นเข้มรองรับ
> ถ้าเปลี่ยนสีแถบ อย่าลืมขยับ `--brandbar`, แท็ก `theme-color` ทั้งสองอัน และค่าใน `paintChrome()` ให้ตรงกัน

> ภาพใน `splash/` iOS เลือกใช้เฉพาะเมื่อความกว้าง ความสูง และ pixel ratio ตรงกับเครื่องเป๊ะ
> รุ่นไหนไม่อยู่ในรายการจะได้จอขาวตอนเปิดแทน ถ้ามี iPhone ขนาดจอใหม่ให้เพิ่มไฟล์กับแท็ก `<link>` คู่กัน
> และ iOS อ่านภาพนี้ตอน "เพิ่มไปที่หน้าจอโฮม" เท่านั้น แอปที่ติดตั้งไว้ก่อนต้องลบแล้วเพิ่มใหม่ถึงจะเห็น

> iOS ไม่รองรับทั้ง SVG และ `data:` URI สำหรับไอคอนบนหน้าจอโฮม จึงต้องมีไฟล์ PNG จริง
> คู่กับแท็ก `<link rel="apple-touch-icon">` เสมอ ไม่อย่างนั้นจะได้ภาพหน้าเว็บย่อส่วนแทนโลโก้

## ติดตั้งเป็นแอป

เว็บเป็น PWA เต็มรูปแบบ เปิดผ่าน https (เช่น Cloudflare Pages) แล้วจะมีปุ่ม
“ติดตั้งเป็นแอปบนเครื่อง” โผล่ขึ้นในแผงควบคุมเอง (Chrome บน Android และเดสก์ทอป)

- Android — ติดตั้งแล้วได้ WebAPK เปิดขึ้นมาเต็มจอ ไม่มีแถบ URL
- iOS — ไม่มีปุ่มติดตั้ง ให้ใช้ แชร์ → “เพิ่มไปที่หน้าจอโฮม” แทน แล้วจะเปิดเต็มจอเหมือนกัน
- ติดแล้วใช้งานตอนไม่มีเน็ตได้ เพราะ `sw.js` แคชไฟล์ทั้งหมดไว้

เวลาแก้โค้ดแล้ว deploy ใหม่ ตัวหน้าเว็บดึงจากเน็ตก่อนเสมอ จึงได้ของใหม่ตั้งแต่เปิดครั้งถัดไป
แต่ถ้าแก้ไฟล์อื่น (ไอคอน manifest) ให้ขยับ `VERSION` ใน `sw.js` ด้วย เพื่อล้างแคชเก่า

## เปิดใช้งานแบบ local

ดับเบิลคลิก `index.html` หรือ

```bash
npx serve .
```

ถ้าจะลองให้เหมือนบน Cloudflare จริง (ส่ง header จาก `_headers` และ redirect `/index.html` ไป `/` ด้วย)

```bash
npx wrangler pages dev .
```

## Deploy ด้วย Cloudflare Pages

push ขึ้น repo แล้วตั้งค่าครั้งเดียวที่ Cloudflare dashboard
**Workers & Pages → Create → Pages → Connect to Git** เลือก repo นี้ แล้วตั้ง build ดังนี้

- Framework preset: **None**
- Build command: *(เว้นว่าง)*
- Build output directory: **`/`**

เว็บจะขึ้นที่ `https://<ชื่อโปรเจกต์>.pages.dev/` และทุกครั้งที่ push ขึ้น `main` จะ deploy ใหม่เอง
โปรเจกต์นี้ชื่อ `soombadminton` — ชื่อโปรเจกต์เปลี่ยนทีหลังไม่ได้ ถ้าจะเปลี่ยนลิงก์ต้องสร้างโปรเจกต์ใหม่

`_headers` คือ header ที่ Cloudflare ส่งไปกับทุกไฟล์ — ห้ามเว็บอื่นฝังแอปไว้ใน iframe (`frame-ancestors 'none'`)
ห้ามเบราว์เซอร์เดาชนิดไฟล์เอง และปิดสิทธิ์กล้อง ไมค์ ตำแหน่ง ฯลฯ ที่แอปไม่ได้ใช้
ส่วน Content-Security-Policy ตัวหลักอยู่ในแท็ก `<meta>` บนสุดของ `index.html` ที่เดียว
ถ้าแอปต้องโหลดอะไรจากที่ใหม่ ให้แก้ตรงนั้น — `_headers` ใส่แค่ `frame-ancestors` ที่ `<meta>` ใส่ไม่ได้

> ทำไมไม่ใช้ GitHub Pages — ทุกเว็บ Pages ในบัญชีเดียวกันอยู่บน origin `<username>.github.io` อันเดียว
> เว็บอื่นในบัญชีจึงอ่าน localStorage และเขียนทับแคชของแอปนี้ได้ ส่วน `.pages.dev` แยก origin ให้ทุกโปรเจกต์
> และ GitHub Pages ตั้ง header เองไม่ได้ จึงกันการฝังใน iframe ไม่ได้

> Cloudflare ตอบ `/index.html` ด้วย redirect ไป `/` — `sw.js` จึงเก็บหน้าแอปไว้ใต้ `./` ไม่ใช่ `./index.html`
> ถ้าเก็บ response ที่เป็น redirect ไว้ เบราว์เซอร์จะไม่ยอมเปิดเป็นหน้าเว็บ แอปที่ติดตั้งไว้จะเปิดไม่ขึ้นตอนไม่มีเน็ต
